# 缺陷目录

每个缺陷族的判定式、真实样例与误判陷阱。代码与 `inspect_pptx.py` 输出一一对应。

## 一、公式结构非法（WPS 缺内容的首要原因）

### M-BADNEST — oMathPara 内嵌 a14:m

**判定式**：`m:oMathPara` 的直接子元素中出现 `a14:m`。

**结构**：
```xml
<m:oMathPara>
  <a14:m>            <!-- 非法：oMathPara 只能放 oMathParaPr 和 oMath -->
    <m:oMath>…</m:oMath>
  </a14:m>
</m:oMathPara>
```

正确写法是把 `a14:m` 放在 `oMathPara` 外面：
```xml
<a14:m>
  <m:oMathPara>
    <m:oMath>…</m:oMath>
  </m:oMathPara>
</a14:m>
```

**后果**：PowerPoint 容错，仍能渲染；WPS 整段不画。这是"独立成行的公式消失"的典型原因。

**实测规模**：207 处，14 份。

**单变量验证（这是本项目最重要的方法）**：只改这一处结构，其余不动，分别用两个引擎渲染同一页，量该公式所在行的墨迹。真实数据：

| 结构 | PowerPoint | WPS |
|---|---:|---:|
| `a14:m > oMathPara > a14:m > oMath`（现状） | 945 | **0** |
| `a14:m > oMathPara > oMath` | 945 | — |
| `a14:m > oMath`（压平，采用这个） | 945 | **895** |

再对 5 份课件做整本对照，每份都构造三个变体（只展开 Fallback / 只拆嵌套 / 两者都做），量 WPS 逐页墨迹：

| 课件 | 只展开 Fallback | 只拆嵌套 | 两者都做 |
|---|---|---|---|
| 01 函数的概念与性质 | +0，0 页 | **+3526，3 页** | +3526，3 页 |
| 04 极限的概念 | +0，0 页 | +0，0 页 | +0，0 页 |
| 10 导数的概念 | +0，0 页 | **+1536，2 页** | +1536，2 页 |
| 14 高阶导数 | +0，0 页 | **+6149，9 页** | +6149，9 页 |
| 17 微分在近似计算中的应用 | +0，0 页 | **+6707，8 页** | +6707，8 页 |

**结论：WPS 缺内容 100% 由 M-BADNEST 造成，展开 Fallback 没有任何渲染效果。** 这张表就是根因证据，也是本技能"必须做单变量实验"这条规矩的来源。

## 一·补、潜在兼容风险（不是 WPS 症状的解释）

### M-BLANKFB — Fallback 分支为空

**判定式**：存在 `mc:AlternateContent`，其 `mc:Choice` 内有文字或公式，而 `mc:Fallback` 内 `a:t` 与 `m:t` 全部为空（或只有一个 `\xa0`）。

**结构**：
```xml
<mc:AlternateContent>
  <mc:Choice Requires="a14">
    <p:sp>… 真正的文字和公式 …</p:sp>
  </mc:Choice>
  <mc:Fallback>
    <p:sp><a:r><a:t>&#160;</a:t></a:r></p:sp>   <!-- 空壳 -->
  </mc:Fallback>
</mc:AlternateContent>
```

**实测结论（务必先读）**：

1. **对 WPS 无影响。** 上面那张 5 份课件的对照表里，"只展开 Fallback" 一列全部是 `+0，0 页`。WPS 实际读取的是 Choice 分支，空 Fallback 从未被用到。
2. **对 PowerPoint 也无影响。** 同上，逐页墨迹零变化。
3. 因此**不要**把这个结构当作"用户报告 WPS 缺内容"的解释。本项目曾据此大规模改动 1265 个形状，事后证明对症状无效。

**它仍然是真实风险**：内容的唯一副本在 Choice 里。真正会走 Fallback 的阅读器（老版本 Office、某些移动端查看器、部分第三方转换工具）会看到空白。

**处理建议**：作为可选的兼容保险，用 `fix_invisible.py --unwrap` 展开。优先级低于所有其他缺陷，且改动前应确认没有更紧迫的问题——因为它会重写大量形状，diff 噪音很大。

## 二、内容为空

### M-EMPTYMATH
`m:oMath` 内没有任何 `m:t` 文本，也没有任何非属性子元素。渲染为空白公式框。

### M-FUNCARG
`m:func` 的 `m:e`（自变量）为空。典型是 `sin`、`cos`、`tan` 被当名词用（"三角函数 sin、cos 有界"），转换时生成了空参数。

**修复**：去掉整个 `m:func` 外壳，把 `m:fName` 里的 run 直接放进父容器。函数名保留，空框消失。

### M-EMPTYFRAC
`m:f` 的 `m:num` 或 `m:den` 为空。无法自动推断原值，只能报告，由人补。

### M-PLACEHOLDER
残留 `单击此处`、`点击此处添加`、`TODO`、`待补`、`占位`。

### M-NOANSWER
同一栏内，某道编号题上下区间里没有任何 `anim-*` 答案形状。

**判定注意**：
- 课件常用两栏或多栏布局，必须**先按左边缘 x 分栏，再在栏内按 y 排序**，否则会误报。
- 一道题可以对应多个答案形状（选项字母 + 解释），不能用 1:1 配对。
- 题干里写了"见例 2，请独立完成""第 9 题与第 7 题相同，略"时，没有答案框是正常的。

## 三、极限表示

### L-AS-SUB
`lim` 被当成普通字母，用 `m:sSub` 加下标：
```xml
<m:sSub><m:e><m:r><m:t>lim</m:t></m:r></m:e><m:sub>…x→0…</m:sub></m:sSub>
```

结果是趋近条件缩成右下角小脚标，而同一页其他公式用的是 `m:limLow`（条件排在 lim 正下方），一页之内两种高低位置并存。

**判定**：`m:sSub` 的 `m:e` 文本恰好是 `lim`。

**修复**：`fix_limit.py` 重建为 `m:limLow`，并迁移 `ctrlPr` 到 `m:limLowPr`。

**实测**：27 处，5 份；同时存在 378 处正确的 `m:limLow`，所以是"混用"而非"全错"。

### L-INCOMPLETE
`m:limLow` 缺 `m:lim`（条件）或 `m:e`（被求极限的式子）。

## 四、指数表示

### E-SPLITRUN
指数被切成独立 run，靠 `baseline="30000"` 抬高字号：
```xml
<a:r><a:t>…x</a:t></a:r>
<a:r><a:rPr baseline="30000" sz="1680"/><a:t>3/2</a:t></a:r>
```

在 PowerPoint 里勉强像上标，换字体、换渲染器或复制粘贴就掉回基线，读成 `x3/2`。用正则扫单个 run 抓不到，必须**看相邻两个 run 的边界**。

**判定**：前一个 run 以 `e`/`x`/`y` 结尾，后一个 run 以数字或 `-`+字母开头且 `baseline` 非空。

**真实样例**：
- `（先化简 x3/2）`、`x³√x = x7/2`（12 课 P15）
- `d(e−x) = e−x·d(−x) = −e−xdx`（16 课 P15）
- `外导分别是 cos、eu、−sin`（13 课 P14，`eu` 应为 `e^u`）

### E-SUPEXPR
整个式子被做成上标（`sup` 内含 `/` 或空格且长度大于 3），版面会挤成一小块。

### E-CARET
正文残留 `^`。

### E-HALF
分数指数写成 Unicode 半字符（`x½`）。

### E-UNISUP
正文用 Unicode 上标字符（`x²`、`eˣ`、`xⁿ`、`y⁽ⁿ⁾`）。与同页 OMML 上标相比字号偏小、基线偏高，肉眼能看出不齐。**这是样式不统一，不是错误**，优先级最低；改动会波及大段正文版式。

## 五、分式表示

### F-IN-TEXT
公式对象内部仍用斜杠写分式，如 `x=1/t`、`y′=−x/y`、`π/2`。与旁边真分式（上下两行、有分数线）高矮不齐。

**排除**：`0/0`、`∞/∞` 是未定式的约定写法，不要改；`a/b` 作为指数（在 `m:sSup` 内）也是常规做法。

### F-LINEAR
整段是普通文字，分式用 `/` 平写，如 `π/2`、`1/x`、`dy/dx`、`sinx/x`。

**排除**：单位 `m/s`、`km/h`；范围 `0/0 型`；选项里作为候选项的 `1/6`。

**优先级说明**：中文教材正文里斜杠写法可接受，属"样式不统一"（P1）。全量改成堆叠分式需逐处调行高，风险高于收益，建议先与用户确认范围。

## 六、版式

### O-OFFCANVAS
形状整体位于画布外（`x ≥ 页宽`、`y ≥ 页高`，或右/下边缘 ≤ 0）。

**真实样例**：判断题的 ✓/× 标记被放在 `x=14.22"`，而页宽只有 13.33"。放映时完全看不见。

**但**：如果题干里已经写了 `（√）`、`（×）`，这些画布外形状只是冗余残留，不影响阅读。

### O-HIDDENDEAD
形状带 `hidden="1"`，但动画时间轴里没有任何 `p:spTgt` 指向它。它会永远不显示。

### 答案位置错乱

不是用坐标判定的，要用 PowerPoint 的真实文字边界：

- 答案文字起点应紧接题干文字终点，同一基线。间距超过约 1 英寸就"脱节"。
- 答案落在**另一道题**的行上，是真缺陷。
- 答案完全覆盖**自己那道题**，通常是点击揭示设计，不要动。

**真实样例（02 课）**：
| 页 | 情况 | 结论 |
|---|---|---|
| P07 | 选择题被放在 y=3.36，压住下一题；它自己的答案 `（C）` 在 y=2.65 | 真缺陷：题目归位到 y=2.65 |
| P10 | 答案 `（0，+∞）` 在 x=2.28，题干文字到 x=4.74 | 真缺陷：答案右移到 4.85 |
| P19/P21/P24 | 答案没对准 `（　）` 空位，压到 `(π/2)`、`=`、`；` | 真缺陷：按空位中心对齐 |
| P23 | 答案 `k=1` 距题干 2 英寸 | 真缺陷 |

## 七、误判陷阱（务必先读）

1. **`a14:m` 计数减少 ≠ 内容丢失。** 展开非法嵌套会让它合法减少。永远用 `<m:oMath`（精确正则 `<m:oMath[ >]`，避免匹配到 `m:oMathPara`）作为不变量。

2. **答案与题干重叠可能是有意设计。** 两者都是 `entr` 动画且位置完全一致时，答案是"出现时盖住题干"。改成左右分列反而破坏设计。

3. **页数与字符数一致 ≠ 内容可见。** 文本存在于 XML 里，但可能因为结构非法而整块不渲染。必须渲染比对。

4. **PowerPoint 渲染零差异 ≠ 修好了。** 如果缺陷只影响 WPS，PowerPoint 侧本来就该是零差异。真正的判据是 WPS 侧墨迹回升。

5. **题号跳号常见且多为有意。** 两栏布局、练习册重复印刷、"第 X 题与第 Y 题相同，略"都会造成跳号。要先读页面上的说明文字再判定。

6. **静态导出的图不能直接判重叠。** 入场动画的形状在静态导出时全部可见，可能显示为重叠，但放映时是依次出现的。

7. **结构可疑 ≠ 就是它导致的。** 本项目实际踩过：看到 1265 个"空 Fallback 的 AlternateContent"，判定为 WPS 缺内容的原因，大规模展开后实测对 WPS 渲染零影响；真正的原因是同一批文件里 207 处 `oMathPara` 非法嵌套。**任何因果判断都要用单变量实验验证**——只改一处，两个引擎各渲染一次，量墨迹。这是本技能最贵的教训。
